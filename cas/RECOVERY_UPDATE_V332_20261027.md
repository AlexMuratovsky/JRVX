# JRVX CAS v332 — проверка игры и возврат из фона

27 октября 2026. **Только локальная версия. Публикация отложена владельцем.**

## Поведение для игрока

В прежнем окне «Связь» у рулетки и блэкджека появилась отдельная кнопка
«Проверить состояние игры». Она получает сохранённый результат с сервера и не
запускает вращение, раздачу или другое игровое действие. При отсутствии результата
игра сообщает, что запрос сохранён. Если сохранённого запроса блэкджека нет,
проверяется только текущая рука. Рулетка без сохранённой ставки сообщает об этом.

После возврата из сна/BFCache индикатор сети и подпись покера обновляются по
актуальному состоянию. Проверки обновления PWA выполняются только при видимой
странице и наличии сети; одновременные проверки объединяются в один запрос.

На маленьком экране окно прокручивается внутри доступной высоты, заголовок и
крестик закреплены. После проверки фокус возвращается на кнопку, если пользователь
не перешёл к другому элементу. Escape закрывает окно и возвращает фокус на «Связь».

## Технические границы

- Новые GET `/api/blackjack/recovery?actionId=UUID` и
  `/api/roulette/recovery?spinId=UUID` получают owner из серверной сессии.
- Только один ожидаемый query-параметр, подготовленные owner-scoped D1 SELECT,
  существующая авторизация, ограничение частоты и запрет кеширования ответов.
- `unknown` означает отсутствие подтверждения, а не отказ. Нет изменения баланса,
  результата, состояния игры или новых финансовых команд при GET.
- Клиент проверяет owner, ID и исходные параметры операции. Для блэкджека receipt
  и свежий snapshot разделены; старый snapshot не откатывает текущую руку.
- Поздний ответ после A→B→A, закрытия окна, ухода в фон или замены pending не
  освобождает запрос. Повторное нажатие объединяется с текущей проверкой.
- Исторический `balanceAfter` рулетки не применяется к кошельку. Баланс читается
  отдельно; шарик выставляется на подтверждённое число без нового вращения.
- Карусель, стили игровых столов, вероятности, правила и финансовые SQL сохранены.
  JRVX ID и другие проекты не изменялись. Реальная оплата остаётся отключённой.

- **789/789 клиентских тестов**, включая новые сценарии восстановления, мобильного
  lifecycle и прежние MG/связь/PWA сценарии против новых контроллеров.
- **64/64 серверных Node-теста**: прежние тесты экономики и миграции, новый lookup
  и повтор 31 сценария настоящего локального Worker/D1/DO против v332. Точные GET
  проверены с аудитом изменений всех строк D1 и разделением аккаунтов.
- **99** проверок синтаксиса JS/MJS; сборка и проверка overlay из **66** файлов.
- Полное приложение в браузере: 320×568, 844×390, 1280×720; подтверждённые результаты
  BJ/рулетки и `unknown` рулетки, фокус, Escape, границы диалога, отсутствие
  горизонтальной прокрутки. На 320×568 шесть действий BJ помещаются в экран.
- Настоящий локальный SW установлен и контролировал страницу. Ошибок/предупреждений
  консоли в проверенных страницах не обнаружено.

Браузер использовал синтетический аккаунт, подготовленные тестовые receipts,
локальный Worker/D1 и запрет денежных POST. Начальная заставка пропущена в fixture;
настоящий вход JRVX ID, физические телефоны, нативная установленная PWA и переход
между опубликованными версиями не проверялись. Игровые кнопки ставок не нажимались.

Evidence: `evidence/cas-state-recovery-v332-20261027/` в workspace, включая логи,
метрики браузера, снимки, SHA-256 сборки и независимую проверку архива коммита.

## Будущая публикация

Требуется новое распоряжение владельца. Сначала повторно проверяются реальные
незавершённые игры, полный namespace комнат и свежая резервная копия CAS. Затем
проводится согласованная MG-миграция и включается проверенный backend v332,
после чего клиент. Ранее загруженный неактивный Worker v330 не содержит новых GET.
Ни миграция, ни переключение backend, ни загрузка файлов на хостинг в этом этапе
не выполнялись.
