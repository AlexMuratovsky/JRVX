## Проверки

Общий клиентский прогон: **360/360 PASS**, без пропусков; ранее было 280 тестов,
добавлены **80** направленных regression tests. Все **34** доступных JavaScript
файла в `cas/public` и `cas/runtime` проходят `node --check`.

| Новый набор | Результат | Доказательство до исправления |
| --- | --- | --- |
| profile | 14/14 | Точный установленный legacy baseline: 7 FAIL/3 PASS на первых 10. Затем combined integration выявила ещё 4 FAIL до hook. |
| admin | 20/20 | Воспроизведены ответы не тому выбранному аккаунту, пустые ответы, ошибки отправки и очереди; последние 5 случаев до правки давали 5 FAIL. |
| experience | 27/27 | Исходные 24 случая: 20 FAIL/4 PASS на старом runtime. Дополнительно исполнены настоящие Pro/Stability wrappers с двойной и выключенной вибрацией. |
| lifecycle cleanup | 5/5 | Старый runtime: 4 FAIL/1 PASS. Независимо проверена последовательность destroy → повторная инициализация → повторный old.destroy. |
| PWA accessibility | 14/14 | Старый runtime: 12 FAIL/2 PASS. |

Profile integration исполняет настоящие progression-v322 и server-account из
identity-account-v327 в порядке установки. Проверены задержанный `/api/me`,
`progress_state`, устаревшая версия и смена владельца. Независимый дополнительный
A→B→A прогон отверг поздние ответы A/B и отобразил свежие 5/17 вернувшегося A.

В браузере использован настоящий PWA runtime и сохранённый CSS с изолированной
локальной страницей: открытие, начальный фокус, Tab, Shift+Tab, Escape, кнопка
закрытия и возврат фокуса проверены. Console errors — ноль. Eligibility iOS
смоделирована; настоящий install prompt и Service Worker отключены в fixture.
Это не тест физического iPhone или установленной PWA.

Coalescing измерен функционально: 100 уведомлений → 1 queued RAF вместо 100.
Это не замер FPS, CPU, памяти или Core Web Vitals. Серверные проверки v327
сохраняются как исторические результаты; неизменённый backend в этом проходе
повторно не тестировался. Production ставки и административные изменения
аккаунтов не выполнялись.

## Оставшиеся границы

**ИСПРАВЛЕНО:** перечисленные воспроизведённые клиентские дефекты, новая сборка
и регрессионное покрытие. Эти исправления подготовлены для проверки в PR.

**НЕ ИСПРАВЛЕНО:** в серверном протоколе admin-ответов нет requestId/target.
Последовательная очередь предотвращает смешение ledger, но принятый запрос без
ответа удерживает очередь до восстановления соединения. Отпускать её по таймауту
небезопасно: поздний пустой ответ невозможно отличить от ответа следующего запроса.
Для полного решения нужен отдельно версионированный серверный контракт.
Настройки haptics Pro и Experience по-прежнему независимы; v328 убирает дубль
результата, но не объединяет эти настройки. Legacy layering сохраняется.

**НЕ ПРОВЕРЕНО:** физические iOS/Android, установленная PWA, реальное качество
аудиоустройств, многочасовой heap/reconnect soak, нагрузка и все региональные сбои.
Тихий initial snapshot не доказывает распознавание любого позднего reconnect
snapshot как старого результата без отдельного server event/token.

**РЕКОМЕНДУЕТСЯ:** следующий отдельный проход — серверная корреляция admin
ответов с совместимостью старых клиентов, затем smoke на физических телефонах,
длительные reconnect/heap сценарии и общий источник настроек вибрации. Для v328
остаётся отдельное решение владельца о публикации, как задано в границах задачи.
