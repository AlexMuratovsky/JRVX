# JRVX CAS — глобальное клиентское обновление v329

24 октября 2026. **Кандидат подготовлен, не опубликован.** На cas.jrvx.ru остаётся
v327. Обновление включает все исправления v328 и добавляет новые возможности
поверх существующих игровых модулей. Тёмное оформление, изображения, правила,
выплаты и серверная экономика сохранены.

## Что изменилось для игрока

**Мои режимы.** В лобби появился компактный каталог пяти существующих маршрутов:
покер с JRVX, публичный и частный покер, рулетка и блэкджек. Режим можно добавить
в избранное, отфильтровать список и вернуться к трём последним выборам. Данные
сохраняются в этом браузере отдельно для каждого подтверждённого аккаунта;
гостевой интерфейс не читает данные прежнего игрока. Нет обещания синхронизации
избранного между устройствами. Отказ хранилища не блокирует навигацию.

**Связь с игрой.** Кнопка в существующем заголовке открывает понятные состояния:
нет интернета, нужен вход, проверяется аккаунт, ожидается соединение и подтверждена
сессия игрового сервера. Наличие интернета само по себе не даёт зелёный статус.
«Проверить связь» обновляет вход и читает состояние аккаунта через существующие
API, не повторяя игровые действия. Проверка ограничена 12 секундами, повторные
нажатия объединяются, поздний ответ после смены владельца или ухода со страницы
не запускает следующий запрос. Прежнее сообщение об успехе исчезает при потере
интернета или handshake, а не противоречит текущему статусу.

**Как играть.** Компактная помощь доступна в лобби, заголовках рулетки/блэкджека
и видимой панели покерного стола. Три вкладки объясняют правила, кнопки, валюту
и ожидание подтверждения запроса. Помощь не запускает раздачу и не предлагает
стратегий выигрыша. Вкладками можно управлять стрелками, Home и End.

**Общие панели.** Помощь и связь используют один механизм диалогов: начальный
фокус, Tab/Shift+Tab внутри, Escape, закрытие по фону и возврат фокуса. Панель не
открывается поверх уже видимого чужого modal, включая подтверждение ALL-IN.
При переключении панелей сохраняется исходная внешняя кнопка возврата.
Обычные клавиши внутри панели не доходят до игровых hotkeys; Enter/Space
сохраняют стандартное поведение её кнопок. Программно ушедший наружу фокус
возвращается в панель до обработки следующей клавиши.

## Контракты и защита от регрессий

Каталог вызывает только существующий `JRVXCASOpenTableFlow` с разрешённым режимом.
Старый `JVRXRoutes.quickPlay` может сразу входить за стол, поэтому его обработчики
не используются даже как fallback. Если безопасного экспорта или исходного
контрола нет, кнопка недоступна. Дополнительно исполнены настоящие retained
`openTables`, `setFlowCopy` и `openFlow`: пять маршрутов открыли выбор валюты,
число join, spin, deal, wallet writes и сетевых операций — ноль. Эти retained
исходники проверены локально; публичные тесты проверяют границу вызова экспорта.

Избранное ограничено пятью известными режимами, недавний выбор — тремя.
Schema, типы, дубли, неизвестные ключи и повреждённый JSON проверяются.
Смена аккаунта очищает отображаемые данные до чтения нового ключа. Наблюдатели
ограничены лобби и конкретными контролами; атрибуты игровых карт не наблюдаются.
Bootstrap имеет четыре ограниченных таймера; destroy очищает timers/observers/RAF.

Connection проверяет `connected` вместе с `handshakeReady` и production identity;
явный `networkVerified=false` или network error запрещает подтверждённый статус.
Виден только один pending check. Скрытая страница останавливает опрос и дальнейшую
цепочку запросов. Существующий API не предоставляет AbortSignal: уже начатый
read может физически завершиться позднее, но новый follow-up после deadline не
выполняется. Подтверждение соединения не выдаётся за результат конкретной игры.

**482/482 клиентских тестов PASS**, без пропусков; **41 JavaScript syntax check PASS**.
К 410 тестам предыдущего кандидата добавлено 72:

В браузере использованы настоящие новые UI-модули, retained CSS/layout и явно
вымышленные аккаунты/состояния. Safe navigation и read-only API заменены fixture;
полный игровой движок, настоящие аккаунты, sockets и mutation API не подключались.
Проверены добавление избранного, recent после перехода, пустое избранное B и
восстановление избранного A, мобильный каталог без горизонтального overflow,
контекстная справка/стрелки/Escape/возврат фокуса и проверка связи: два mock read,
ноль игровых запросов. Дополнительно проверены offline/auth/connecting состояния.

**12 раскладок:** покер, блэкджек и рулетка × 320×568, 390×844, 844×390,
1280×820. В каждой две новые кнопки находятся на экране, проходят hit testing
и не перекрывают другие контролы. Scroll dimensions трёх игровых экранов равны
viewport в этих fixtures; рулетка остаётся на одном экране. Отдельно исправлены
два найденных при интеграции случая: скрытый gamehead seated-покера и выход
справки рулетки за край на 320 px. Это не испытание физических телефонов.

Независимый review обнаружил противоречивый success feedback после offline;
исправление проверено двумя регрессионными тестами с API state и DOM. Проверка
retained v84 выявила ещё одну границу: document-bubble `f/c/r` вызывал Fold/Call/Raise
даже при фокусе на кнопке нового modal. Панели теперь изолируют всплытие keydown.
Тест использует точную retained регистрацию обработчика; в браузере тот же handler
с counter-only игровыми кнопками дал ноль действий для F/C/R внутри справки.
Enter после Shift+Tab закрыл справку и вернул фокус, также без игровых действий. Других
подтверждённых межмодульных дефектов в этом проходе не осталось.
Локальное evidence: `evidence/cas-global-update-v329-20261024/`, включая журналы,
responsive JSON до/после исправления, browser states и screenshots.

## Сборка, публикация и откат

`cas/deploy/cas-ecosystem.zip`: **45 public files**, **1 635 080 bytes**.
SHA-256: `ed3b59633cb42a7bc74a879c65c2d4cc521d7a0c4df509f608ef39b4315e5785`.
Прирост к кандидату v328 — 18 995 bytes. CRC, пути, активные подключения,
source/package bytes, уникальность script src и precache проверены.

Восемь новых immutable assets: четыре runtime и четыре CSS для hub/connection/
guide/panels. **Все 35 общих payloads v328 побайтно сохранены** относительно
`d0669ff3cd28fedcf6a073e57e356b95e6c904a3`; **26 общих payloads production v327**
также не изменены. Cache suffix — `recovery-20261024-v329-shell`, 169 уникальных
precache URL. Старые игровые assets не удаляются.

Публикация — отдельный шаг по разрешению владельца из границ исходной задачи.
Overlay предназначен для существующего webroot, не для пустого хостинга.
При переходе прямо с production v327 нужны все новые пути v328 и v329 из ZIP:
сначала immutable assets, затем index/SW; проверить все precache URL и bytes.
Сохранить прежние index/SW и versioned файлы. Откат — оболочка production v327
из `8539ff5106f03bfc3e3956747fb2b85e7bd598d4` при сохранённых legacy assets.
Backend, D1, DNS, секреты и рабочие игровые данные этому релизу менять не требуется.

**ИСПРАВЛЕНО / ДОБАВЛЕНО:** описанные возможности и интеграционные дефекты;
проверенная сборка включает исправления v328 без переписывания игровых правил.

**НЕ ИСПРАВЛЕНО:** прежний admin-протокол без requestId, legacy layering и прочие
границы из отчёта v328. Это клиентское обновление не закрывает серверный техдолг.

**НЕ ПРОВЕРЕНО:** физические iOS/Android, установленная PWA/её upgrade v329,
многочасовой heap/reconnect soak, нагрузка и региональные сбои. Серверные suites
v327 остаются историческим evidence и не объявляются повторно запущенными.

**РЕКОМЕНДУЕТСЯ:** после проверки кандидата — отдельная публикация с сохранением
rollback, smoke на физических телефонах, затем серверная корреляция admin-ответов
и длительные reconnect/heap проверки. Наличие новых панелей не означает полного
покрытия всех legacy-модулей или отсутствие любых ошибок CAS.
