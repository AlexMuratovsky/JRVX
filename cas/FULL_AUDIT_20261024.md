## Версия и границы проверки

Исходная версия клиента — опубликованный v326 / CAS 3.0.17, commit
`003732db980c5e74599a5a63c8be3998adced54c` в `AlexMuratovsky/JRVX`.
Изучены README, отчёт от 23 октября, все доступные активные клиентские bundles,
`runtime/`, `server/`, тесты, HTML, Service Worker, сборка overlay и CAS CI.
Повторно проверены прежние исправления; выводы этого отчёта основаны на новых запусках.

Публичный репозиторий содержит overlay и вспомогательные серверные материалы,
**не полный исходный сервер CAS**. Для серверных проверок использована частная
копия фактически установленного Worker `jrvx-cas-v300`. Через Cloudflare выполнены
только чтение версии/исходника и чтение определений таблиц/индексов/триггеров.
Боевые пользовательские строки для тестов не выгружались.

`27f2e145-f4ab-4249-b6e6-9c39f7eb4460`, deployment
`1a80c8d9-87aa-4188-a5c9-6b3ae0281488` (100%).
SHA-256 канонического ES-модуля —
`9cd0bbd6fae00ff478f0758928900abe915ee1596b7f68b7733ab9300b3d4679`.
Cloudflare multipart-export добавляет завершающий LF: его SHA-256 —
`6063525d71cec996c237a5f1aa4fb303d99387dd46ef3218cb2e8d4f7809253b`.
Это тот же сервер с owner guard, который опубликован в предыдущем релизе.
В текущем кандидате серверный код не меняется.

Для Miniflare восстановлены определения всех 13 таблиц CAS и исходные ограничения;
проверены REST, D1 и Durable Objects. Все записи, пользователи, сессии, операции и

Недоступны полноценные production E2E с финансовыми действиями, физические iPhone/
Android, Safari/WebKit, системная клавиатура, реальные safe-area и динамическая
адресная строка телефона, GPU/heap-профилирование и длительное распределённое
нагрузочное испытание Cloudflare. Локальный Miniflare не доказывает отсутствие
ошибок при любом сбое распределённой production-инфраструктуры.

### Сервер, деньги и online poker

Через фактические REST handlers проверены конкурентные повторения одного ID:
exchange, roulette, Blackjack deal и stand проводят эффект один раз.
Добавленные **только в локальный D1** 39 AFTER-mutation triggers учитывают изменения
всех 13 таблиц: 18 запросов с чужим `ownerId` дают **ноль D1 writes**.
Совместимость со старым клиентом без ownerId проверяется через серверную сессию;
клиентский ownerId не становится источником авторизации.

PokerRoom проверен в реальном Miniflare: duplicate buy-in не списывает повторно;
ALL-IN перед disconnect, reconnect и повтор прежней команды сохраняют результат;
cashout сохраняет сумму средств; два почти одновременных HTTP action с одной
ревизией принимают ровно одно действие; реальный 15-секундный DO alarm завершает
просроченный ход. Проверены замена HTTP connection generation и поздние события.
Команда `admin_set_balances` от обычного синтетического USER отклоняется сервером.
Проверки HMAC/AES, origin, revocation, receipt conflict и ledger также повторены.

Локальный poker engine и точный серверный evaluator проверены на heads-up правилах:
52 уникальные карты, ранги/кикеры/ничьи, blinds, min raise, ALL-IN, uncalled excess,
завершение раздачи. Multiway side pots не вводились: существующая архитектура heads-up.
Blackjack покрывает hit/stand/double/split/insurance, natural, split aces, soft aces,
bust/push и однократный расчёт. Клиентская анимация не начисляет средства.

Две настоящие local Workers дополнительно подтверждают полный маршрут CAS → ID:
synthetic registration/verification, выдача code с PKCE, JWKS signature, создание
CAS cookie с Secure/HttpOnly/SameSite=Lax и сохранение mapping аккаунта.
После принудительного локального истечения access token два параллельных CAS
auth-запроса вызывают одну настоящую refresh rotation в ID. Invalid state и уже
использованный code отклоняются. ID logout инвалидирует CAS userinfo, CAS logout
удаляет CAS credentials. Письма перехватываются локально; реальной отправки нет.

### Рулетка и анимации

Повторно измерены **0°, 30°, 60°, 90°, 135°, 180°, 225°, 270°, 315°**.
Least-squares circle fit выполнен по золотым пикселям на радиусах 0,610 / 0,499 /
0,130 от R, с четырьмя отсечениями residual >1,25 px. Нулевая/недостаточная выборка
не засчитывается. Снимки сделаны после загрузки artwork; преждевременные fallback
кадры исключены из измерения, а не объявлены исправленной геометрией.

Диск содержит ровно 37 европейских секторов и точный порядок/цвета 0–36. Проверены
логический Canvas world при DPR/resize, cache rotor, совпадение server target с
конечным pocket, ошибки draw, отмена/закрытие, Repeat/Double/Clear и смена account.
Timeline тестируется на шагах **30/60/120 FPS**; это симуляция времени, не измерение
фактической частоты кадров на устройстве. Новые/раскрытые карты анимируются один раз,
повторный server render не перезапускает уже известные карты.

### Service Worker, обновление и rollback

Пятнадцать VM-тестов исполняют фактический SW source с контрактной моделью
CacheStorage/fetch: завершение precache до skipWaiting; отказ установки сохраняет
предыдущую оболочку; activate удаляет только старые CAS caches; API/auth/callback/
socket/mutations/cross-origin не кэшируются; online shell refresh; HTTP ошибки;
offline fallback; stalled navigation abort; static cache и retained v326 bundles.
Дополнительно выполнен настоящий browser lifecycle на отдельном localhost origin:
baseline v326 активируется с 161 cache entry; candidate с намеренным 404 становится
redundant, старый controller и его 161 entry сохраняются; полный v327 активируется
с 161 entry; rollback возвращает активный v326 и его cache. Реальные исходники SW,
синтетические игровые assets: это не полный CAS E2E или установленная iOS PWA.
Дополнительно текущий Worker отдаёт свежие static и navigation HTTP responses
с `Vary: *`, хотя настоящий browser Cache.put отклоняет такие ответы с TypeError.
В первом случае проверены HTTP 200, fresh marker и отсутствие сохранённого entry;
во втором реальная навигация показывает новый marker вместо старого cached index.
Продление lifetime организовано через [ExtendableEvent.waitUntil](https://developer.mozilla.org/en-US/docs/Web/API/ExtendableEvent/waitUntil).

### Дополнительная инъекция серверных сбоев

**13/13 новых групп** проходят на реальных локальных D1/SQLite Durable Objects:
buy-in/rebuy/cashout × потеря ответа после фактического D1 commit / ошибка index
перед DO room commit; cashout активной руки после обоих progress commits;
потеря ответа progression batch; сохранение pending plan и восстановление каждой
из трёх финансовых операций после Miniflare dispose/recreate.

Проверены conservation wallet + planned escrow (10 000 / 20 000 MS), однократные
ledger/history/progress/receipt, очистка plan и восстановление D1 room index.
Outbound attempts — ноль. Новых серверных дефектов в этих сценариях не найдено.
Это **явно инструментированный локальный подкласс PokerRoom**: исходный ES-модуль
сохранён точным byte prefix, исходные игровые/recovery методы наследуются, а
wrapper теряет ответ после настоящего batch или бросает ошибку в index.
Эти 13 групп не описываются как запуск полностью неизменённого Worker и не
заменяют 19 групп без такой instrumentation. Production source не менялся.
Локальный restart не доказывает корректность любого регионального Cloudflare сбоя.

Публичные тесты и сборка пригодны для GitHub Actions. Full recovered Worker и
расширенные local server harness не публикуются: исходник production остаётся
частным. Поэтому эти серверные группы пока нельзя повторить в публичном CI без
отдельного безопасного source/access workflow.

## Производительность и legacy

Измерены размер/целостность overlay: v326 — 1 590 573 bytes, v327 — **1 598 742 bytes**,
изменение **+8 169 bytes**. Новый shell заменяет прежние активные JS пути, а не
подключает обе версии. В HTML нет дублирующихся script src. Неизменившиеся
25 versioned файлов в обоих ZIP побайтно совпадают.

Профиль CPU/GPU, heap snapshots, Core Web Vitals и длительная память до/после
не получены. В дополнительном инструментированном Canvas-прогоне измерены 240
отрисовок на viewport 1100×820, backing canvas 458×458: median draw **0,4 ms**,
p95 **1,1 ms**, max **5,5 ms**, warm-up **0,8 ms**. Это wall-time вызова draw;
GPU completion и производительность физического телефона он не измеряет.
Браузер в фоне ограничивал frame interval примерно 1003,5 ms, поэтому эти данные
не дают надёжного device-FPS benchmark; числа реального FPS или ускорения до/после
намеренно не приводятся. По коду rotor
остаётся одной переиспользуемой поверхностью с пределом 2048×2048, без нового
Canvas на каждом кадре. Lifecycle/animation cleanup проверен функциональными
тестами, но это не заменяет многочасовой heap soak.

Массовая чистка legacy не выполнялась: из публичного overlay невозможно доказать
отсутствие всех зависимостей старой установки. Изменены конкретные воспроизведённые
границы, без массовой переписи и изменения игровых контрактов.

## Итог и оставшиеся проверки

**ИСПРАВЛЕНО:** 20 воспроизведённых групп клиентских дефектов, расширение CI,
82 новых regression tests и rollback-safe v327 overlay. Доступные обязательные

**НЕ ИСПРАВЛЕНО:** подтверждённых и оставленных без исправления дефектов из списка
выше нет. Известный технический долг — legacy layering и отсутствие приватного
полного CAS backend в публичном CI; они не объявляются исправленными.

**НЕ ПРОВЕРЕНО:** физические Safari/iOS/Android, клавиатура/safe-area, настоящий
production OIDC через REG.RU и браузерные cookies после будущей публикации, реальная
доставка почты, физически установленная iOS/Android PWA, многочасовая память, массовые
reconnect/load, распределённый crash между DO и D1 и обрывы во всех точках commit.
Эти ограничения не позволяют называть CAS полностью протестированным или обещать
отсутствие любых финансовых/сетевых ошибок. Продуктивные ставки не выполнялись.

**РЕКОМЕНДУЕТСЯ:** продолжить smoke на настоящем
iPhone/Safari и Android; затем проверить staging PWA upgrade/rollback с настоящими CAS assets и настоящий
OIDC proxy path без ставок. Дальше вынести recovered backend в контролируемый
приватный source/CI, добавить failure injection на DO↔D1 границе и длительный
reconnect/heap soak. Legacy сокращать только после подтверждения зависимостей.
